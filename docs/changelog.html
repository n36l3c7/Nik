Changelog

Nik follows Semantic Versioning. This page summarises each release; the complete, line-by-line history is CHANGELOG.md in the repository, and every version is published under Releases.

2.11.2 2026-11-10

  • fixed Samples stored by releases before 2.7.0 are made readable by the analysis workers at startup and on re-upload (the Code and Capabilities views failed on them); the workers report an unreadable sample plainly.

2.11.1 2026-11-10

  • fixed podman compose up --build on RHEL: every image is named with its registry (docker.io/…) instead of being resolved through registry.redhat.io; the capa worker no longer uses tmpfs uid / gid options, which Podman rejects.

2.11.0 2026-11-10

  • added Admins add their own capa rules in Settings; the capa worker checks each one, and their matches are marked custom.
  • changed The Code view lists every function of large binaries (the 3,000 limit is gone), and opening a function stays fast.
  • changed Decompiling a function on demand takes seconds instead of a new analysis; the up-front pass decompiles the code worth reading first.
  • changed Passwords are hashed with bcrypt directly (passlib removed); existing passwords keep working.

2.10.0 2026-11-10

  • added Capabilities view: what a sample's code can do according to Mandiant capa, mapped to MITRE ATT&CK and the Malware Behavior Catalog, with links to the functions where each capability was found.
  • added capa runs in its own isolated worker after upload and Re-analyse, one sample at a time.
  • added The Code view shows each function's capabilities, and Start here ranks unrecognised functions with capabilities higher.

2.9.0 2026-11-10

  • added Code view triage: library code recognised by FLIRT signatures or by the Rust crate its panic paths name is hidden by default, with the crates listed and each function's origin shown.
  • added Start here: the unrecognised functions worth reading first (suspicious APIs, indicators used, complexity).
  • added The strings each function uses, and a Used by column in the IOC table that opens the function.
  • added Rename and comment functions, per sample, in the list, graphs and pseudo-C.
  • added Admins upload FLIRT signatures in Settings.

2.8.1 2026-11-09

  • fixed Switching functions in the Code view with a graph open could blank the whole application.
  • added A rendering error in one view now stays in that view, with a button to reload it; the rest of Nik keeps working.

2.8.0 2026-11-09

  • added Decompiled panel in the Code view: the pseudo-C of each function from Ghidra's decompiler (rz-ghidra, already in the analyzer image), with highlighting, links from calls to the called functions and suspicious APIs in red. Functions are decompiled up front within a time budget and the rest on first open.
  • fixed The analyzer worker survives rizin crashes on large binaries instead of losing the whole analysis.

2.7.0 2026-11-09

  • added Code view: functions, call graph and control-flow graphs of a sample, disassembled by an isolated rizin worker and laid out with ELK (orthogonal edges, loops on the side, full disassembly per block, pan, zoom and minimap). Functions that reach suspicious APIs are highlighted and can be flagged.
  • added Analyzer worker service in the Compose stack: read-only sample store, non-root, read-only filesystem, no capabilities, memory / CPU / time limits, no internet access.

2.6.0 2026-11-09

  • added Structure view for samples: PE headers, sections with entropy, imports, exports, resources and imphash (via pefile); ELF and Mach-O with Nik's own parsers.
  • added YARA scanning with a built-in rule set and admin-managed rules (Settings → YARA rules, validated before saving); matches raise the sample severity. Re-analyse runs the current engine again on a stored sample.

2.5.0 2026-11-09

  • added Malware Analysis tab: samples stored on the server (by SHA-256, never executed) and analysed statically: hashes, file type, entropy chart, strings and indicators of compromise, flaggable and visible in the timeline. Downloads as an AES zip with the infected password or a custom one. New REST endpoints under /api/samples.
  • added Built-in malware ruleset for the SOC engine (injection, anti-analysis, persistence, C2 patterns, encoded PowerShell, throwaway TLDs, ransomware, credentials).

2.4.0 2026-11-09

  • added End-to-end smoke test (Playwright) of the whole stack, run in CI: first-run setup, sign-in, new incident, demo data, timeline and tail panel.
  • added This documentation site, served from /docs on GitHub Pages.
  • added Prettier for the frontend and ruff format for the backend, checked in CI; the code base was reformatted once, with no behaviour change.
  • changed Large browser histories (hundreds of thousands of visits) stay responsive: each URL is parsed once per event, text columns sort with a shared collator, the table search never blocks typing, and a flag no longer rebuilds the Timeline or the tail panel.
  • security Frontend build dependencies flagged by npm audit updated (Vite 6.4.6, PostCSS, nanoid, browserslist, source-map-js); development-time tools only.

2.3.1 2026-11-09

  • added ESLint (React and hooks rules) for the frontend and Ruff for the backend; CI runs both.
  • fixed The Events, Commands, Artifacts and Timeline tabs no longer recompute their memoized rows on every render when an incident has no flags; backend errors keep their original cause; unused code removed.

2.3.0 2026-11-06

  • added tail -f side panel: the latest 60 timestamped events of the open incident, newest at the bottom, toggled from the tab bar and remembered per tab.
  • changed Terminal look, step 2: every page (Summary, Browser Forensics, Command History, Endpoint Artifacts, Timeline, Network Logs, Settings, Backup) uses the design tokens. Analyst flags use the green accent, SOC rows their severity colour.
  • changed The dark: Tailwind variant is gone: Nik is dark only.

2.2.0 2026-11-06

  • added Terminal look, step 1: named colour tokens, bundled Inter and JetBrains Mono fonts (no CDN), sign-in and first-run screens with the NIK banner and a live $ nik status box.
  • changed UI kit, sidebar, header, tab bar and OS picker with square corners, monospace labels and the green accent; the header shows host / user with the OS.
  • changed The light theme and its toggle were removed.

2.1.0 2026-11-06

  • added ASCII skull loaders, generated at any size, with eyes that look around and blink; opening an incident shows the real download progress and a Cancel button.
  • changed Loading, error and empty states use the skull; busy buttons use the inline micro skull. Skulls stay still when the OS asks to reduce motion. The spinner is gone.

2.0.0 2026-11-04

  • added Several profiles per browser ("Default", "Profile 1", "Work"…), each with its own files and data; the timeline and flags name the profile; profile parameter on the upload endpoint and the Cortex XSOAR command; Alembic migration 0003_browser_profiles.
  • breaking Browser data moved to data.browser.browsers[id].profiles[profileId]; the upload response target is now browser/<id>/<profile>/<source>. The server converts pre-2.0.0 data on create, patch, fetch and restore, so old exports and backups still import.

1.2.0 2026-11-04

  • added Safari in Browser Forensics (macOS): History.db, Downloads.plist and Bookmarks.plist (Reading List included), with a dependency-free property list parser for binary and XML plists; Safari uploads through the REST API.

1.1.0 2026-11-04

  • added 304 Not Modified on If-None-Match, JSON Merge Patch (RFC 7396) on PATCH, os in the summary listing, frontend unit tests in CI.
  • changed Lazy loading: sign-in downloads only the light incident list; an incident's artifacts are fetched when it is opened, behind a non-blocking loading state; edits send only what changed.

1.0.0 2026-07-11

  • added First release: browser, command history and endpoint artifact analysis, super-timeline, SOC detection rules, case management, full backup, authentication, audit log and the external REST API.
