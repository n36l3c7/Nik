Configuration

Nik is configured with environment variables: the backend reads its own, the Compose file reads a root .env. Detection rules and business hours are edited in the app and shared by every analyst.

Backend

Environment variables, optionally from backend/.env (see backend/.env.example).

Variable Default Purpose
DATABASE_URL sqlite:///./nik.db SQLAlchemy URL. Production: postgresql+psycopg://nik:PASS@host/nik (the password must be URL-encoded).
DB_PASSWORD + DB_USER / DB_HOST / DB_PORT / DB_NAME — Alternative to DATABASE_URL: the app assembles the PostgreSQL URL itself with escaping, so the password may contain any character.
SECRET_KEY dev-insecure-change-me Signing / entropy secret. Set a long random value in production.
COOKIE_SECURE true Secure flag on the session cookie (HTTPS only). Set false only for plain-HTTP local development, otherwise the browser drops the cookie and sign-in does not stick.
SESSION_TTL_HOURS 12 Session lifetime.
SAMPLE_STORE ./samples Directory of the raw malware samples, one file per SHA-256, never executed. Exclude it from the server's antivirus and include it in backups: the database holds only the analysis results. The Compose stack mounts a named volume here.
SAMPLE_MAX_MB 100 Per-file size limit for sample uploads.
YARA_RULES app/yara Directory of the built-in YARA rule files (*.yar). Rules added by admins live in the database and are compiled together with these.
ANALYZER_URL · ANALYZER_TOKEN — Base URL of the rizin worker and the shared secret it requires. Without them the Code view reports "not configured" and everything else works.
ANALYZER_TIMEOUT 600 Seconds rizin may spend on one sample before the worker stops it.
ANALYZER_DECOMPILE_SECONDS 300 Part of the analysis time spent decompiling functions up front; the others are decompiled when first opened. Set on the analyzer service.
CAPA_URL · CAPA_TOKEN — Base URL of the capa worker and the shared secret it requires. Without them the Capabilities view reports "not configured" and everything else works.
CAPA_TIMEOUT 1800 Seconds capa may spend on one sample (large binaries take ten minutes or more).
DOCVIEW_URL · DOCVIEW_TOKEN — Document viewer worker (attachment previews) and its shared secret. Without them the Preview buttons are disabled.
BROWSER_URL · BROWSER_TOKEN — Isolated browser worker and its shared secret. Without them HTML attachments and links do not open.
PCAP_URL · PCAP_TOKEN — Packet capture worker (Wireshark's engine) and its shared secret. Without them captures are stored but not analysed.
PCAP_MAX_MB 500 Largest packet capture accepted, in MB.
ENRICHMENT_WORKER true Background thread of the automatic threat-intelligence lookups; false turns it off (Check now still works).
RUN_CREATE_ALL true Create missing tables on startup. Set false when Alembic owns the schema (alembic upgrade head from backend/).
RATE_LIMIT_DEFAULT per-IP limit Request rate limit applied to the API, in slowapi notation (e.g. 60/minute).

Compose

Variables of the root .env (see .env.example), read by docker-compose.yml.

Variable Default Purpose
DB_PASSWORD nik PostgreSQL password, shared by the db and api services.
SECRET_KEY — Backend secret. Use a long random value, e.g. openssl rand -hex 32.
COOKIE_SECURE false Keep false while anyone still uses plain HTTP on :8080; set true once everyone is on HTTPS.
WEB_PORT 8080 Host port the UI is published on (plain HTTP).
WEB_TLS_PORT 8443 Host port the UI is published on (HTTPS).
TLS_HOSTNAME localhost Name embedded in the auto-generated certificate (CN + SAN): what users type in the browser.
SESSION_TTL_HOURS 12 Session lifetime.
ANALYZER_TOKEN — Shared secret between the api and analyzer services. Use a long random value.
ANALYZER_MAX_FUNCTIONS 20000 Safety cap on the functions listed per sample.
ANALYZER_WARM_SESSIONS · ANALYZER_WARM_IDLE 1 · 600 Analysed sessions the rizin worker keeps open so that decompiling on demand takes seconds (0 disables; about 1 GB each on a large binary), and how long an unused one stays open.
ANALYZER_MEMORY · ANALYZER_CPUS 4g · 2 Memory and CPU limits of the rizin worker container.
CAPA_TOKEN · CAPA_TIMEOUT — · 1800 Shared secret between the api and capa services (different from the analyzer's) and the per-sample time limit.
CAPA_MEMORY · CAPA_CPUS 4g · 2 Memory and CPU limits of the capa worker container.
DOCVIEW_TOKEN · BROWSER_TOKEN · PCAP_TOKEN — Shared secrets between the api and the docview, browser and pcap services: long random values, all different.
BROWSER_MAX_SESSIONS 3 Isolated browser sessions open at once (idle ones close after 5 minutes, any after 30).
PCAP_MAX_MB 500 Largest packet capture accepted, in MB.
DOCVIEW_MEMORY · BROWSER_MEMORY · PCAP_MEMORY 2g · 2g · 4g Memory limits of the workers (sharkd keeps an open capture in memory: a few times its size); the *_CPUS variables set their CPU limits.
Two things that bite over plain HTTP: a session cookie with COOKIE_SECURE=true is never stored by the browser, and the in-browser parsers need a secure context for some APIs (the clipboard, for one). Use HTTPS as soon as you can.

In-app settings

Opened from the header (gear icon); shared by every analyst and stored on the server.

Detection rules

Suspicious-keyword rules (regular expressions with a label, a description and a severity) matched against URLs, titles and file names; built-in command and endpoint rulesets run in addition, each only on its own kind of entry.

Business hours

Start and end hour, with an option to treat weekends as outside hours. Events outside the window are marked and counted as medium severity.

Accounts, API keys, webhooks

Admins create analyst accounts, issue API keys with a role, scopes and an optional expiry, and subscribe webhook URLs to platform events.

YARA rules, FLIRT signatures, capa rules

Admins add YARA rule sets (compiled before they are saved), upload FLIRT signatures (.sig or .pat) that the analyzer worker applies on top of rizin's own, so more library code is recognised and hidden in the Code view, and add capa rules (checked by the capa worker before they are saved) matched with capa's bundled set. All apply to samples analysed from then on: use Re-analyse on older ones.

Backup

Full platform export and import (users, incidents, audit log, settings) for admins. Take one before every upgrade.

Upgrades

Pull the new release and rebuild (docker compose up -d --build). Data persists in PostgreSQL; new tables are created on startup, and releases that add a migration run alembic upgrade head in the Docker image. Upgrading to 2.0.0 rewrites every incident once (browser data moves into a "Default" profile): on large databases the first start takes longer, so take a backup first.
