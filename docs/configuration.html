Configuration

Nik is configured with environment variables: the backend reads its own, the Compose file reads a root .env. Detection rules and business hours are edited in the app and shared by every analyst.

Backend

Environment variables, optionally from backend/.env (see backend/.env.example).

Variable Default Purpose
DATABASE_URL sqlite:///./nik.db SQLAlchemy URL. Production: postgresql+psycopg://nik:PASS@host/nik (the password must be URL-encoded).
DB_PASSWORD + DB_USER / DB_HOST / DB_PORT / DB_NAME — Alternative to DATABASE_URL: the app assembles the PostgreSQL URL itself with escaping, so the password may contain any character.
SECRET_KEY dev-insecure-change-me Encrypts the secrets stored in the database (threat-intelligence API keys, TLS key logs of captures). Without it they cannot be read again, so keep it with the backups. The default is for development: the container refuses it, and any value shorter than 16 characters.
SECRET_KEY_PREVIOUS — Earlier values of SECRET_KEY, separated by commas or lines, kept while it is being changed: what they encrypted is still read, is re-encrypted with the new key and read back. deploy/secrets.sh rotate secret-key sets and removes it.
STORE_KEY dev-insecure-store-key-change-me Seals every file of the store on the disk. It is in no database and in no backup. The default is for development: the container refuses it, and any value shorter than 32 characters; without a store key the server stays up and says so instead of starting.
STORE_KEY_PREVIOUS — Earlier store keys, kept while the store key is being changed: files under them are still read, and their keys are put under the new one. deploy/secrets.sh rotate store-key sets and removes it.
<NAME>_FILE — For every secret (SECRET_KEY, STORE_KEY, their _PREVIOUS, DB_PASSWORD, the *_TOKEN of the workers, METRICS_TOKEN): a file that holds it, read in place of the variable (a mounted secret). An empty file counts as none; a secret given both ways, or in a file that cannot be read, stops the server with a sentence that says which. The workers read their token the same way.
STORE_SEAL_MBPS 40 How fast the store of a server from before 6.8 is sealed, in megabytes read a second (0: as fast as the disk goes).
NIK_NO_STORE_KEY, NIK_STORE_API_URL — Set by the Compose file for the automation container: it holds neither the store nor its key (1) and asks the backend at this address for the files a step needs.
NIK_SKIP_MIGRATIONS — Set to 1 by the Compose file for the automation container, which shares the backend's image: its entrypoint checks the secrets and leaves the migrations and the check of the store key to the backend. Never set it for the backend.
METRICS_TOKEN — A bearer token /api/metrics accepts beside the scrape token made on the health page (Settings → System → Health). With neither, the route answers to nobody.
AUDIT_KEY, AUDIT_KEY_FILE made by deploy/init-env.sh on a new install; otherwise derived from SECRET_KEY The key the entries of the audit log are signed with (or the file that holds it). The same for the backend and the automation worker, and given to no other container. hex:… for a key written as bytes. Set or changed with deploy/secrets.sh rotate audit-key.
AUDIT_KEY_PREVIOUS, AUDIT_KEY_PREVIOUS_FILE — Earlier keys, separated by commas or line breaks, written by the scripts that change or restore a key: the entries they signed stay verifiable (deployment guide).
NIK_WEB_TLS web:443 Where the web server listens for TLS, as the backend reaches it: the health page reads the dates of the certificate it presents there. Empty when there is none to read; the host and port of your own proxy on a manual install.
PROMETHEUS_MULTIPROC_DIR /tmp/nik-metrics in the image A directory, in memory, where the API processes add up the requests they counted, so that /api/metrics gives the same totals whichever process answers. Unset, each process counts for itself.
COOKIE_SECURE true Secure flag on the session cookie (HTTPS only). Set false only for plain-HTTP local development, otherwise the browser drops the cookie and sign-in does not stick.
SESSION_TTL_HOURS 12 The longest a session lasts, until an admin sets another under Settings → Sign-in and sessions: what is set there wins.
TRUSTED_PROXIES empty (web in Compose) Who X-Forwarded-For is believed from: host names, addresses or networks, separated by commas. From anybody else the header is ignored and the client is known by the address of its connection. The waits after failed sign-ins and the administrators' networks go by it.
SAMPLE_STORE ./samples Directory of the files Nik keeps (samples, one per SHA-256, never executed; e-mails, captures, mailboxes), each sealed under STORE_KEY. The database holds only the analysis results. The Compose stack mounts a named volume here, in the backend alone.
SAMPLE_MAX_MB 100 Per-file size limit for sample and e-mail uploads.
ARTIFACT_MAX_MB 500 Per-file size limit for the evidence files the server parses (POST /api/incidents/{id}/upload). A larger file is refused with 413 while it is being read.
YARA_RULES app/malware/yara Directory of the built-in YARA rule files (*.yar). Rules added by admins live in the database and are compiled together with these.
ANALYZER_URL · ANALYZER_TOKEN — Base URL of the rizin worker and the shared secret it requires. Without them the Code view reports "not configured" and everything else works.
ANALYZER_TIMEOUT 600 Seconds rizin may spend on one sample before the worker stops it.
ANALYZER_DECOMPILE_SECONDS 300 Part of the analysis time spent decompiling functions up front; the others are decompiled when first opened. Set on the analyzer service.
CAPA_URL · CAPA_TOKEN — Base URL of the capa worker and the shared secret it requires. Without them the Capabilities view reports "not configured" and everything else works.
CAPA_TIMEOUT 1800 Seconds capa may spend on one sample (large binaries take ten minutes or more).
DOCVIEW_URL · DOCVIEW_TOKEN — Document viewer worker (attachment previews) and its shared secret. Without them the Preview buttons are disabled.
BROWSER_URL · BROWSER_TOKEN — Isolated browser worker and its shared secret. Without them HTML attachments and links do not open.
PCAP_URL · PCAP_TOKEN — Packet capture worker (Wireshark's engine) and its shared secret. Without them captures are stored but not analysed.
PCAP_MAX_MB 500 Largest packet capture accepted, in MB.
MAILBOX_MAX_MB 2048 Largest mailbox accepted (an mbox, or a zip or tar archive of a Maildir), in MB.
PST_MAX_MB 4096 Largest Outlook PST accepted, in MB. It is converted by the document worker on its pst-work volume, a disk, not memory: the volume needs about two and a half times the PST free while it is converted (the worker checks, and says how much is missing). Without the volume the worker converts in memory and takes a PST of 500 MB at most. The shipped nginx lets a mailbox upload of 4200 MB through, which covers this default and that of MAILBOX_MAX_MB: to raise either beyond it, raise client_max_body_size of the mailbox location in frontend/nginx/nginx.conf (or in your own nginx file) as well.
ENRICHMENT_WORKER true Background thread of the automatic threat-intelligence lookups and of the bulk checks; false turns it off (Check now still works). It asks only the sources that are on: the connectors with an instance.
API_BACKGROUND true What the backend does by itself in threads of its own: the check of the workers (it tells the administrators when one is down, see When a worker is down) and the scans of addresses that playbooks ask for. false turns both off: no notice about a worker, and a Scan an address node waits five minutes and fails.
NIK_PACKS_CATALOGUE the release packs of Nik's repository The address (https) of the index of the catalogue of content packs, until an administrator sets another in Settings. Empty (NIK_PACKS_CATALOGUE=): no catalogue, packs come as files.
NIK_PACKS_DIR empty A folder inside the backend container whose packs (folders with a pack.yml, or .nikpack files) are installed at start when they are not here or are older. Mount it read-only with a Compose override. Nothing in it is checked against a signature.
NIK_BACKUP_DIR the volume backups A directory of the host where the server writes its backups, in place of the volume of the stack: another disk than the data. Inside the containers it is /app/backups (BACKUP_DIR, for an installation without containers).
NIK_UPGRADE_REHEARSAL true Before a release migrates the database, its migrations are tried on a copy made from the snapshot. false skips that rehearsal, never the snapshot, on a database too large to copy at every upgrade.
NIK_WAL_ARCHIVE on The archive of the log of PostgreSQL, which brings the database back to a moment and is what a standby replays. off starts the database without it: no recovery to a moment, no standby. Read by the db container.
NIK_ARCHIVE_TIMEOUT 300 Seconds after which PostgreSQL closes a segment of its log while something is written: the most that is lost when the host dies and its last segments had not left it. Lower loses less and writes more small files. The screens take what they say can be lost from the same variable, and count no less than 10.
NIK_WAL_ARCHIVE_DIR the volume wal-archive A directory of the host where the archive and the base backups are kept, in place of the volume of the stack: another disk than the data. What it holds is in clear, like the data directory of the database. Inside the backend it is /app/wal-archive (WAL_ARCHIVE_DIR; empty on an installation without containers, where nothing of the recovery runs).
NIK_STANDBY_INBOX empty On a standby: the directory of this host the first host sends its copies to. deploy/standby.sh init and rejoin write it; do not set it by hand. Empty, an empty folder of the repository is mounted in its place.
NIK_SERVER_NAME TLS_HOSTNAME What this server calls itself to the other host of a pair, at most 120 characters: it is in the file a promotion leaves, and in the sentence a replaced server shows. A name set on the Backup page wins over it; with neither, the name of the machine is used.
RECOVERY_MEMORY · RECOVERY_CPUS 1g · 2 The limits of the recovery container, which takes the base backups and runs the recovery test.
NIK_RECOVERY_WAIT 3600 Read by deploy/restore.sh --to and deploy/standby.sh from the environment of the shell, not from .env: how many seconds a replay of the log is waited for.
NIK_TRANSFER_PASSPHRASE — Read by deploy/standby.sh secrets export and import from the environment of the shell, when nobody is there to type it: the passphrase the file of keys is sealed under, 12 characters or more. Never put it in .env.
AUTOMATION_WORKER container Where the loop that makes playbooks run lives: container (the automation service of the Compose stack), inline (a thread of the backend, for an install without that container) or off (no event is recorded and nothing runs).
AUTOMATION_CONCURRENCY 4 How many steps of playbooks run side by side (1 to 32).
AUTOMATION_MAX_ACTIVE_RUNS 200 How many runs may be in progress at once on the server; more are refused.
AUTOMATION_RUNS_KEPT 500 How many finished runs each playbook keeps; older ones are deleted with their steps.
AUTOMATION_HTTPS_PROXY · AUTOMATION_NO_PROXY empty A proxy for what playbooks send outside, and the hosts reached without it. Leave empty when the server has a direct or transparent way out.
SANDBOX_TOKEN generated The shared secret of the script sandbox. deploy/init-env.sh writes it, and adds it to the .env of an install made before 4.1.
SANDBOX_URL — Base URL of the script sandbox (http://sandbox:8750 in the Compose file, which sets it). Without it a step that runs a script fails and says the sandbox is not configured.
SANDBOX_TIMEOUT · SANDBOX_MAX_TIMEOUT 10 · 60 How long a script may run, in seconds: by default, and at most.
SANDBOX_MEMORY_MB 256 The memory one script may use, in MB.
SANDBOX_MEMORY · SANDBOX_CPUS 512m · 1 The limits of the sandbox container.
AUTOMATION_MEMORY · AUTOMATION_CPUS 1g · 2 The limits of the automation container.
RUN_CREATE_ALL true Create missing tables on startup. Set false when Alembic owns the schema (alembic upgrade head from backend/).
RATE_LIMIT_DEFAULT 600/minute Requests each client address may make, in slowapi notation. Signing in has a limit of its own, 10 a minute.

Compose

Variables of the root .env, read by docker-compose.yml. Create the file with deploy/init-env.sh: it copies .env.example and makes every secret, each a random value. On a new install the secrets go into files of the directory NIK_SECRETS_DIR names and their lines stay in .env, empty; a server from before 6.8 keeps the values here until deploy/secrets.sh move is run. The variables marked required have no default: Compose stops when one is not named at all, and the containers refuse a secret that is missing from both places or is an example value.

Variable Default Purpose
DB_PASSWORD required PostgreSQL password, shared by the db and api services. It is set when the database is first created; to change it later, change it in PostgreSQL too.
SECRET_KEY required Encrypts the secrets stored in the database. Keep it with the backups. To change it: deploy/secrets.sh rotate secret-key.
STORE_KEY required Seals every file of the store. Only the api container is given it. Without it the server stays up and says so instead of starting. To change it: deploy/secrets.sh rotate store-key.
NIK_SECRETS_DIR — The directory that holds the secrets as files (./secrets on a new install), each mounted into the containers that use it. Unset on a server that keeps its secrets in this file: the empty files of deploy/no-secrets are mounted in their place.
STORE_SEAL_MBPS 40 How fast a store from before 6.8 is sealed, in megabytes a second.
PCAP_MEMORY_FILE_MB 64 The packet capture worker is sent the capture it reads: one of this size or less stays in its memory, a larger one goes to its pcap-work volume while it is open.
COOKIE_SECURE true The app is served over HTTPS only, so the session cookie is Secure. Leave it.
WEB_PORT 8080 Host port for plain HTTP. It serves nothing: every request is redirected to HTTPS.
API_MEMORY, API_CPUS 4g, 4 Limits of the backend container, which parses the evidence.
WEB_MEMORY 512m Memory limit of the web container (nginx).
METRICS_TOKEN — A bearer token for /api/metrics, accepted beside the scrape token made on the health page. The route is reached through the web port and answers to a token only (deployment guide).
WEB_TLS_PORT 8443 Host port the UI is published on (HTTPS).
TLS_HOSTNAME localhost Name embedded in the auto-generated certificate (CN + SAN): what users type in the browser.
SESSION_TTL_HOURS 12 The longest a session lasts, until an admin sets another in Settings.
TRUSTED_PROXIES web Who the backend believes about the client's address: the web container. Change it only if something else than this stack's nginx hands requests to the backend.
ANALYZER_TOKEN — Shared secret between the api and analyzer services. Use a long random value.
ANALYZER_MAX_FUNCTIONS 20000 Safety cap on the functions listed per sample.
ANALYZER_WARM_SESSIONS · ANALYZER_WARM_IDLE 1 · 600 Analysed sessions the rizin worker keeps open so that decompiling on demand takes seconds (0 disables; about 1 GB each on a large binary), and how long an unused one stays open.
ANALYZER_MEMORY · ANALYZER_CPUS 4g · 2 Memory and CPU limits of the rizin worker container.
CAPA_TOKEN · CAPA_TIMEOUT — · 1800 Shared secret between the api and capa services (different from the analyzer's) and the per-sample time limit.
CAPA_MEMORY · CAPA_CPUS 4g · 2 Memory and CPU limits of the capa worker container.
DOCVIEW_TOKEN · BROWSER_TOKEN · PCAP_TOKEN — Shared secrets between the api and the docview, browser and pcap services: long random values, all different.
BROWSER_MAX_SESSIONS 3 Isolated browser sessions open at once (idle ones close after 5 minutes, any after 30).
PCAP_MAX_MB 500 Largest packet capture accepted, in MB.
MAILBOX_MAX_MB 2048 Largest mailbox accepted (an mbox, or a zip or tar archive of a Maildir), in MB.
PST_MAX_MB 4096 Largest Outlook PST accepted, in MB. It is converted by the document worker on its pst-work volume, a disk, not memory: the volume needs about two and a half times the PST free while it is converted (the worker checks, and says how much is missing). Without the volume the worker converts in memory and takes a PST of 500 MB at most. The shipped nginx lets a mailbox upload of 4200 MB through, which covers this default and that of MAILBOX_MAX_MB: to raise either beyond it, raise client_max_body_size of the mailbox location in frontend/nginx/nginx.conf (or in your own nginx file) as well.
DOCVIEW_MEMORY · BROWSER_MEMORY · PCAP_MEMORY 2g · 2g · 4g Memory limits of the workers (sharkd keeps an open capture in memory: a few times its size); the *_CPUS variables set their CPU limits.
What the stack enforces. The backend runs as an unprivileged user on a read-only filesystem with memory, CPU and process limits, like the workers. It alone mounts the store of files and holds its key: the workers are sent the file a job needs. nginx serves HTTPS only and sends a Content-Security-Policy, X-Content-Type-Options, X-Frame-Options, Referrer-Policy and HSTS with every page. Rate limits and the waits after failed sign-ins go by the client address, as nginx sees it. Container logs are rotated at 20 MB.

Tuning and worker variables

Rarely needed; the defaults suit a single server.

Variable Default Purpose
LOG_LEVEL INFO Verbosity of the backend log.
WEB_CONCURRENCY 2 Backend worker processes (gunicorn).
DB_USER, DB_HOST, DB_PORT, DB_NAME nik, localhost, 5432, nik The other parts of the PostgreSQL address, with DB_PASSWORD.
DB_POOL_SIZE, DB_MAX_OVERFLOW, DB_POOL_RECYCLE 5, 10, 1800 Database connections kept per backend process, extra ones under load, and their lifetime in seconds.
DB_STATEMENT_TIMEOUT_MS 30000 A query that runs longer is cancelled (PostgreSQL only).
RATE_LIMIT_STORAGE_URI memory:// Where rate-limit counters are kept; a Redis URL shares them between processes and hosts.
FORWARDED_ALLOW_IPS 127.0.0.1 (empty in Compose) gunicorn's own list of proxies whose headers rewrite the address of a connection. Leave it empty: the backend decides itself whom to believe (TRUSTED_PROXIES). With *, as the Compose file had it before 6.7, the header is believed from whoever sends it; the policy page warns when it finds that.
RUN_CREATE_ALL true (false in the image) Create the tables at start-up without Alembic: for development on SQLite only.
ANALYZER_MAX_JOBS, CAPA_MAX_JOBS, DOCVIEW_MAX_JOBS, PCAP_MAX_JOBS, SANDBOX_MAX_JOBS 2, 1, 2, 2, 4 Analyses each worker runs at once (scripts, for the sandbox); more are answered "busy".
ANALYZER_FILES_MB, CAPA_FILES_MB, PCAP_FILES_MB 1024, 1024, 16384 How much each of these workers holds, in MB, of the files the backend sent it. When a new file does not fit, the ones it is not working on go first; a single file larger than this is refused.
DOCVIEW_PST_TIMEOUT 3600 Seconds the document worker gives the conversion of one PST. The backend waits 3900 seconds for the answer, so a longer time here is cut there.
DOCVIEW_PST_TMP_MAX_MB 500 Largest PST the document worker converts in memory, in MB, when it has no pst-work volume it can write to.
TLS_SELFSIGNED_DAYS 825 Days the certificate the web container makes for itself is valid. Read once, when the certificate is made: one that is already in the web-certs volume is left alone.
API_STOP_GRACE, ANALYZER_STOP_GRACE, CAPA_STOP_GRACE, DOCVIEW_STOP_GRACE, PCAP_STOP_GRACE 20 each Seconds a process that is asked to stop gives what it has in flight (the requests of the backend, the analyses of a worker) before it exits. Each is read in the environment of its own container, and has to stay under the stop_grace_period of that service in the Compose file (40 s for the backend, 30 s for these four workers; the sandbox and the isolated browser have no such variable and get 20 s): see Stopping and restarting the stack.
DOCVIEW_TIMEOUT, DOCVIEW_MAX_PAGES, DOCVIEW_MAX_MB 90, 20, 50 Seconds a preview may take, pages rendered, largest document.
BROWSER_IDLE, BROWSER_LIFETIME 300, 1800 Seconds an isolated browser session lasts without an action, and in all.
PCAP_TIMEOUT, PCAP_RPC_TIMEOUT, PCAP_MAX_SESSIONS, PCAP_SESSION_IDLE 900, 300, 2, 900 Seconds to summarise a capture and to answer one question about it; captures kept open at once, and how long an unused one stays open.
NIK_BACKUP_WAIT, NIK_ROTATE_WAIT 21600 each Seconds deploy/backup.sh waits for the backup it asked for, and deploy/secrets.sh for a change of key to be verified. Read from the environment of the shell that runs the script, not from .env.

The worker variables are read by the worker containers, and TLS_SELFSIGNED_DAYS by the web container: to change one that docker-compose.yml does not pass, add it to that service's environment.

In-app settings

Opened from the gear at the bottom of the rail; shared by every analyst and stored on the server. Detection rules, business hours and the IOC allowlist are the analysts' working settings; the rest is for admins.

Detection rules

Suspicious-keyword rules (regular expressions with a label, a description and a severity) matched against URLs, titles and file names; built-in command and endpoint rulesets run in addition, each only on its own kind of entry.

Business hours

Start and end hour, with an option to treat weekends as outside hours. Events outside the window are marked and counted as medium severity.

Accounts and API keys

Admins create accounts, change their name, roles or password, disable them, and issue API keys with roles and an optional expiry. Every user changes their own password under My account. Webhooks are subscribed through the API (/api/webhooks).

YARA rules, FLIRT signatures, capa rules

Admins add YARA rule sets (compiled before they are saved), upload FLIRT signatures (.sig or .pat) that the analyzer worker applies on top of rizin's own, so more library code is recognised and hidden in the Code view, and add capa rules (checked by the capa worker before they are saved) matched with capa's bundled set. All apply to samples analysed from then on: use Re-analyse on older ones.

IOC allowlist

Known-good indicators (addresses, networks, domains) left out of the Indicators tab and never sent to a threat-intelligence source.

Indicators found

Admins set whether the fields and the context of an incident are read for indicators as it comes in (on by default), which types are kept, that private addresses and what is known to be benign are left out, how many an incident may be given this way (500 until it is set, from 1 to 1000), the paths that are never read, and whether the automatic look-ups ask about what was found (they do not, by default). An instance that fetches can be told apart from the setting, in the Fetch tab of its own form. See Indicators found by themselves.

Bulk actions

Admins set, under Settings → System → Bulk actions, how many rows one bulk action takes (5,000; 1 to 50,000), up to how many are done before the answer (50; 0 to 500: more goes on in the background and survives a restart), and above how many a closing of incidents is confirmed by typing (100; deleting always is). There is no variable for them: they are kept in the database, and changed without a restart. See Select many, and act on them at once.

Report header, mail analysis, threat intelligence

Admins set the organisation's name and logo on reports, the organisation's own mail domains and the mail servers whose authentication results are trusted, and for threat intelligence which indicator types are looked up automatically and how long an answer stands. The sources themselves are connectors: a source is on when an instance of its connector is, and its keys are the keys of that instance (Connectors).

My account, audit log

Everyone changes their own password under My account and reads the audit log, which the server writes. Backups are set in Settings → System → Backup, by admins: their schedule, what is kept, the passphrase and the copy off the server (Backups). At the foot of the same page, Recovery to a moment: when the base backups are taken, how many days one can go back, the delay of the second host that is warned about, how often the archive is proven, and the name of this server for the other host (the screen).

Upgrades

Pull the new release and rebuild (docker compose up -d --build). Data persists in PostgreSQL and in the sample store; the image brings the schema up to date at every start. When a release has migrations to run, it first takes a snapshot of the database into the backup directory and tries the migrations on a copy (Updates, and the snapshot before each), and deploy/rollback.sh puts the snapshot back if the upgrade went wrong.
