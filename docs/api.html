REST API

Nik can be driven without the browser. The API is the same one the web app uses, so anything the UI does — create, edit and delete incidents, add notes, upload raw artifact files (parsed server-side) — is available programmatically under /api.

Interactive documentation

Open /api/docs on a running server (for example https://localhost:8443/api/docs) for the Swagger UI. It is public to view and always in sync with the server. Click Authorize, paste an API key, and every endpoint gains a Try it out button. The OpenAPI document is at /api/openapi.json; generate a typed client from it, e.g. openapi-generator generate -i https://HOST/api/openapi.json -g python.

Authentication

Write endpoints accept either a browser session or an API key, sent in the X-API-Key header:

curl -H "X-API-Key: nik_XXXXXXXX…" https://localhost:8443/api/incidents

Keys are created and revoked in the app under Settings → API keys (admin only). The plaintext key is shown once, at creation, and carries permissions bound to it:

  • role — analyst (incidents, notes, uploads, read settings) or admin (also users, backup, keys, webhooks).
  • scopes — read / write; a read-only key can fetch but not mutate.
  • expiry — optional; an expired key is rejected.

Every change is recorded in the audit log by the server, whoever makes it: a key appears as api:<label>, a session as its username.

A browser session is opened with POST /api/auth/login ({ username, password }, at most 10 attempts a minute per address) and closed with POST /api/auth/logout; GET /api/auth/me returns the signed-in user and GET /api/auth/bootstrap says whether any account exists. After ten wrong passwords in a row an account answers 429 for five minutes; a disabled account answers 403.

Endpoints

Method & path Purpose
GET /api/incidents List incidents. Query: limit / offset, q / host / username, status (open, in_progress, closed), assignee (a username; empty for unassigned), view=summary (light rows without the document body). Total in the X-Total-Count header.
GET /api/incidents/{id} One incident, with an ETag: its revision, which changes at every write, whoever makes it. Send If-None-Match to get 304 while your copy is current.
POST /api/incidents Create / upsert (id generated if omitted). The response carries the ETag.
PATCH /api/incidents/{id} application/json: replace the given top-level fields. application/merge-patch+json: apply an RFC 7396 merge patch (nested merge, null deletes). Honors If-Match (412 on a stale version) and answers with the new ETag.
DELETE /api/incidents/{id} Delete an incident.
POST /api/incidents/{id}/notes · PATCH / DELETE …/{noteId} Add / edit / remove notes.
POST /api/incidents/{id}/upload Upload a raw artifact file (multipart). ?async=true → 202 { jobId }.
GET /api/jobs/{id} Poll an async upload job.
GET /api/incidents/{id}/iocs The incident's indicators of compromise (type, value, sources, count, first/last seen, number of other incidents, allowlisted), indexed from every tab each time its data is saved.
GET /api/iocs/lookup?type=&value= Every incident an indicator appears in ("where seen").
GET /api/iocs/shared Indicators seen in two or more incidents, most widespread first.
GET /api/iocs The IoC library: every indicator an incident holds, an analyst added or a list keeps, with its reputation, lists, tags, TLP and expiry. Query: q, type, verdict (malicious, suspicious, harmless, flagged, none), origin, list, expired, sort, dir, offset, limit. Returns iocs, total, counts and the number of unseen alerts.
POST /api/iocs/parse · POST /api/iocs Read text without saving ({ text }: free text, CSV, STIX 2.1, MISP or Nik's JSON; returns the items and a summary), then add: { items | text, tags, note, tlp, expires, list: { id | name, watch }, check, origin }. Each indicator is saved on its own; list also groups them; check starts a bulk check. PATCH /api/iocs/item edits tags, note, TLP and expiry; POST /api/iocs/remove takes a scope out of the library.
GET/POST /api/iocs/lists · GET/PATCH/DELETE …/{id} Lists of indicators (name, description, tlp, watch; scope to fill a new one). POST …/{id}/items and POST …/{id}/items/remove add and take out. Removing a list takes its author or an admin.
GET /api/iocs/lists/{id}/feed The list as it is now, for machines: format (txt by default, csv, json, stix, misp), types, flagged. Signed with X-API-Key or HTTP Basic with the key as the password. Allowlisted and expired indicators are left out; a TLP:RED list answers 403.
POST /api/iocs/export Download a scope: { scope, format, fields, defang, flaggedOnly, allowlisted, expired }. Fields: type, value, verdict, score, tags, first_seen (the default), last_checked, sources_flagging, per_source, incidents, lists, note, tlp, origin, added_by, expires.
POST /api/iocs/check · GET /api/iocs/checks[/{id}] Bulk reputation check of a scope. dryRun returns the plan only (indicators to ask, answers reused, never sent, and per source the requests against today's quota); otherwise the check is queued and worked through in the background: poll its status (running, waiting for a quota, done, stopped), done and total. POST …/checks/{id}/stop ends it.
GET /api/iocs/alerts · POST /api/iocs/alerts/seen Incidents that came to hold an indicator of a watched list, newest first; mark them seen.
POST /api/incidents/{id}/report The incident report as a PDF (default) or HTML. Body, all optional: format, lang (en/it), tlp, sections, executiveSummary, detections (SOC rule hits with ATT&CK ids). Missing options come from the incident's saved report settings. scope: flagged (the default: only what the analysts flagged) or all (everything in the incident).
GET /api/search?q= Global search (2+ characters): incidents by name, host or user; indicators from every incident (3+ characters); samples by hash prefix (6+ hex characters) or file type.
GET /api/incidents/{id}/iocs/export ?format=csv|stix|misp: CSV, a STIX 2.1 bundle or a MISP event; types= narrows the types, allowlisted values are left out unless allowlisted=true.
POST /api/incidents/{id}/samples Upload a malware sample (multipart file): stored by SHA-256, analysed statically, attached to the incident. Re-uploading a known file reuses its analysis.
GET /api/samples/{sha256} · …/strings Metadata and full analysis (hashes, type, entropy blocks, indicators, first 5,000 strings); /strings?q=&minLength=&encoding= scans the stored file on demand.
GET /api/samples/{sha256}/download The sample inside an AES-256 zip. ?password= (default infected), ?name= for the file name inside the archive. Recorded in the audit log.
DELETE /api/incidents/{id}/samples/{sha256} Detach the sample from the incident; it stays as an artifact until the artifact is deleted.
POST /api/samples/{sha256}/reanalyse Run the current analysis engine and YARA rules again on the stored file.
POST /api/incidents/{id}/mails Analyse an e-mail (multipart file, .eml or Outlook .msg) and attach it to the incident: route, SPF/DKIM/DMARC through DNS and as reported by your servers, sender, links, body, attachments, score and verdict (phishing ≥ 70, suspicious 40–69, clean). 422 for a file that is not an e-mail.
GET /api/mails/{sha256} · POST …/reanalyse · GET …/source The full analysis and the incidents holding the message; analyse it again; the .eml as text.
GET /api/mails/{sha256}/attachments/{path}/bytes · …/download A slice of an attachment (≤ 64 KiB, base64; offset, length) for the hex view; the attachment in an AES-256 zip (password, default infected, audited). path is the index, 2.0 inside the attached message at index 2.
POST /api/incidents/{id}/mails/{sha256}/attachments/{path}/sample Send an attachment to Malware Analysis as a sample of the incident.
POST /api/mails/{sha256}/attachments/{path}/preview The attachment's first pages as PNG, rendered by the document viewer worker (LibreOffice with macros disabled, pdfium). GET /api/previews/status says which preview workers are configured.
POST /api/browser/sessions · …/{id}/action · DELETE …/{id} The isolated browser: open an HTML attachment or a link (network true or false, incident to keep the network log, width and height of the page, audited), replay clicks, typing, keys, scrolling and navigation, send or hold submissions (policy, audited), get a screenshot back; close the session. The answer lists the session's tabs ({ id, title, url, active }): the windows the page opened. The actions tab and closeTab (with the tab's id) show or close one, and resize (width, height, kept between 640×400 and 2560×1600) draws the pages at another size. GET …/{id}/network lists the session's requests.
POST/GET /api/incidents/{id}/captures · GET /api/captures/{id} Upload a pcap or pcapng (up to PCAP_MAX_MB, optional TLS key log), analysed in the background; list the incident's captures; the capture's state and summary (hosts, DNS, HTTP, TLS server names, submissions, beacons, objects, Expert Info).
POST /api/captures/{id}/rpc Read-only calls to Wireshark's engine: frames (display filter, paging, time format), frame (protocol tree and bytes), follow, tap (Export Objects, Expert Info), check, complete, status.
GET /api/captures/{id}/objects/download · …/file · …/har · …/requests An exported object in a protected zip, the capture file, an isolated browser session as HAR 1.2, its requests (one in full with …/requests/{entryId}). Downloads are audited.
PUT/DELETE /api/captures/{id}/keylog · POST …/reanalyse · DELETE /api/incidents/{id}/captures/{captureId} Add or remove a TLS key log (stored encrypted), analyse again, take the capture out of the incident (it stays as an artifact).
DELETE /api/incidents/{id}/mails/{sha256} Detach the message from the incident; it stays as an artifact until the artifact is deleted.
GET /api/artifacts · GET /api/artifacts/{id} The files, e-mails and captures analysed on their own or in incidents, newest first, each with the incidents that reference it. Query: kind (file, mail, pcap, url), q, tag, mine, linked, limit / offset. One artifact also lists its parents and children (the e-mail an attachment came from, the objects taken out of a capture). Ids are file-<sha256>, mail-<sha256>, pcap-<capture id>.
GET /api/artifacts/lookup?sha256= Is this file already known? The artifacts with that digest, to check before an upload.
POST /api/artifacts/files · …/mails · …/captures Analyse a file, an e-mail or a capture without an incident (multipart file; optional form field incident to link it at once; keylog for a capture). The analysis is then read from the samples, mails and captures endpoints.
POST /api/artifacts/urls Scan an address with the isolated browser ({"url", "incident"?}; defanged text accepted, private and internal hosts refused). Returns the scan and its artifactId (url-<id>); an address already scanned is returned as it is (known).
GET /api/urls/{id} · POST …/rescan · GET …/screenshot The scan's state (queued, running, done, error), verdict, score and result: final address, navigation chain, forms, findings with points, the capture of the visit, and scripts: per script its kind (external or inline), address, size, SHA-256, entropy, share of obfuscated text, recognised library, findings (id, severity, points, title, line, start, end, excerpt) and iocs. Visit it again; the screenshot as JPEG. GET …/scripts/{n} adds the script's code (text, never run); …/scripts/{n}/download is the script in a zip, password infected.
POST /api/artifacts/{id}/links · DELETE …/links/{incidentId} Link the artifact to an incident ({"incidentId"}) or take it out. A file or an e-mail can be in several incidents, a capture in one. Unlinking never deletes the artifact.
POST /api/artifacts/{id}/attachments/{path}/sample · POST /api/artifacts/{id}/objects/sample Analyse an e-mail's attachment, or an object exported from a capture, as a file artifact related to its source (optional ?incident=).
PUT /api/artifacts/{id}/tags · DELETE /api/artifacts/{id} Replace the tags ({"tags": []}, 12 at most). Delete the artifact: its file, its analyses and its reference in every incident.
POST /api/artifacts/export · POST /api/artifacts/import Export { ids, files } (500 artifacts at most) as a zip: manifest.json (format: nik-artifacts), records/<id>.json with each analysis and, only with files: true, the original files in an AES-encrypted files.zip (password infected). Import (admin, multipart file) adds the artifacts the server does not have and returns { added, ids, existing, skipped: [{ name, reason }] }; a file whose SHA-256 is not its artifact's is refused. Both are audited.
GET/POST /api/samples/{sha256}/code Disassembly by the rizin worker: state (none / queued / running / done / error) and, when done, binary info and functions with their calls. POST (re)starts it.
GET /api/samples/{sha256}/code/functions/{addr} Control-flow graph of one function: basic blocks, instructions, jump / fail successors.
GET /api/samples/{sha256}/code/functions/{addr}/decompiled Pseudo-C of one function (rz-ghidra) with highlight spans and call targets: stored by the analysis, or decompiled on first request and kept.
GET/POST /api/samples/{sha256}/capabilities Mandiant capa on the capa worker: state (none / queued / running / done / error / unsupported) and, when done, the capabilities with their ATT&CK and MBC mappings and addresses. POST (re)starts it.
GET /api/samples/{sha256}/annotations · PUT …/annotations/{addr} Analysts' names and comments for the sample's functions, shared by every incident holding the file. PUT takes { name, comment }; both empty removes the annotation (returns null). 409 before the sample is disassembled.
GET/POST /api/capa-rules · PUT/DELETE …/{id} · POST …/validate capa rules (YAML, one each) matched with capa's bundled set (admin to change). The capa worker checks a rule before it is saved; a rule another enabled rule matches cannot be renamed, disabled or deleted.
GET/POST /api/flirt-signatures · PUT/DELETE …/{id} FLIRT signatures (.sig or .pat, multipart name + file, up to 32 MB) applied by the analyzer worker from the next disassembly (admin to change; any caller may list).
GET/POST /api/yara-rules · PUT/DELETE …/{id} · POST …/validate Admin-managed YARA rule sets, compiled with the built-in ones (admin to change; any caller may list). A source must compile before it is saved.
GET /api/enrichment/providers · POST …/{id}/keys · DELETE …/{id}/keys/{keyId} Threat-intelligence providers with the state of each of their keys (keys: id, last four characters, label, ok / rejected / unreadable; never the key). Add a key ({ key, label }, at most 10 per provider, 409 for one already stored) or remove one (admin, audited). Lookups rotate over a provider's keys. PUT/DELETE …/{id}/key still replace or remove all of a provider's keys.
GET /api/enrichment?type=&value= · POST /api/enrichment/check What is known about an indicator: summary (verdict, weighted score 0–100, flagged, checked, counts), results (per provider: verdict, summary, link, data with the details, history of the last ten answers, expired, hasRaw), notAsked, retentionDays, refresh (providers whose answer has expired and should be asked again) and why the value is never sent, if so. POST asks every usable provider now ({ type, value, force }, 422 for a private, internal, allowlisted or TLP:RED value, audited).
GET /api/enrichment/raw?type=&value=&provider= The provider's whole answer as a JSON download (404 when none is stored). The same indicator opens in the app at /ioc/<type>?v=<value>.
GET /api/settings Read the shared detection rules, business hours, IOC allowlist, report header and Mail Analysis settings (mail: { orgDomains, trustedAuthServers }) and threat-intelligence options (enrichment: { auto, retentionDays: { ip, url, hash }, refreshExpired, virustotal: { engines, relations, comments }, providers }, never the keys). PUT replaces them (a session, or a key with the write scope): the report header, the mail settings and the threat-intelligence options change only for an admin, and are left as they are for anyone else.
GET/POST/DELETE /api/webhooks Manage event subscriptions (admin).
GET/POST /api/users List and create accounts (admin): { username, password, role }, the password at least 8 characters. While no account exists the first POST needs no authentication and creates an admin.
PATCH /api/users/{id} Change an account (admin): any of { username, role, password, disabled }. A new name is carried to the incidents assigned to the account; a new password or disabled: true ends its sessions. 400 when it would leave no admin able to sign in, or change the caller's own role.
DELETE /api/users/{id} Delete an account (admin); never the caller's own nor the last admin.
PUT /api/users/me/password The signed-in user changes their own password ({ currentPassword, newPassword }, session only); the account's other sessions end.
GET /api/users/names The usernames an incident can be assigned to (any signed-in user or key).
GET/POST/DELETE /api/keys API-key management (admin).
GET/POST /api/backup/{export,import} Full platform backup (admin).
GET /api/audit Audit log, newest first: limit, offset, q, actor, incidentId. The log is written by the server.
POST /api/audit Record an action done in the browser alone (session only). Only incident.export is accepted; anything else is 400.
DELETE /api/audit Clear the log (admin); the new log starts with an entry saying who did.
GET /api/health · /api/ready · /api/metrics Liveness · readiness (database) · Prometheus metrics. None needs authentication, so the bundled nginx does not publish /api/metrics: scrape http://api:8000/api/metrics on the compose network, with Authorization: Bearer … when METRICS_TOKEN is set.

Endpoints marked admin accept an admin session or an admin-role API key; any other key gets 403.

Uploading files

POST /api/incidents/{id}/upload takes a multipart file plus query parameters that route it to the right parser, mirroring the app's tabs. The server parses the raw file and merges the normalized result into the incident.

Evidence comes from hosts that may be compromised, so parsing is bounded: a file larger than ARTIFACT_MAX_MB (500 MB) is refused with 413; a browser database is opened read-only with its schema untrusted and a time budget, and one that exceeds it is refused with 400 and the reason. Downloads carry the file's own name in any script (filename*, RFC 5987), with path separators, control characters and text-direction marks replaced. 

# Browser history (Chromium History SQLite → data.browser.browsers.chrome)
curl -H "X-API-Key: $KEY" -F file=@History \
  "https://localhost:8443/api/incidents/$ID/upload?tab=browser&browser=chrome&source=history"

# Shell history (.bash_history → data.commands.shells.bash)
curl -H "X-API-Key: $KEY" -F file=@.bash_history \
  "https://localhost:8443/api/incidents/$ID/upload?tab=commands&shell=bash"

# Endpoint artifact (cron file or tool CSV → data.endpoint.categories.persistence)
curl -H "X-API-Key: $KEY" -F file=@crontab \
  "https://localhost:8443/api/incidents/$ID/upload?tab=endpoint&category=persistence&source=cron"

# Windows event log (.evtx → data.eventlogs.channels.Security), parsed in the background
curl -H "X-API-Key: $KEY" -F file=@Security.evtx \
  "https://localhost:8443/api/incidents/$ID/upload?tab=eventlogs&async=true"
  • tab=browser needs browser (chrome / firefox / edge / brave / opera / safari) and source (history / bookmarks / shortcuts / places; Safari: history / downloads / bookmarks), plus an optional profile: the profile name, matched case-insensitively and created if missing (default Default).
  • tab=commands needs shell (bash / zsh / fish / powershell).
  • tab=endpoint needs category (execution / persistence / fileaccess / usb) and source (the source key, e.g. cron).
  • tab=eventlogs needs nothing else: the channel comes from the .evtx file and the result lists it in channels. Only the curated event IDs are kept, records left after a log clear are recovered, and the channel's meta keeps the file's SHA-256 and the log's coverage.

Automation features

  • Pagination and filtering on GET /incidents and /audit; view=summary lists at scale, then fetch one incident's full document.
  • Optimistic concurrency: send the ETag back as If-Match on PATCH; a stale write gets 412. Read the incident again, apply your change to it and retry with the new ETag (each PATCH returns it). A whole-array value such as notes replaces what is stored, so an If-Match is what keeps two writers from dropping each other's items. Without the header the patch is applied to whatever is stored. Every write of an incident is serialised by a row lock.
  • Conditional GET: If-None-Match returns 304 Not Modified while nothing changed; the check reads only the version column.
  • Partial updates: application/merge-patch+json updates only the nested members you send, e.g. {"flags": {"<key>": null}} removes one flag.
  • Idempotency: an Idempotency-Key header on POST notes / upload makes retries safe.
  • Scopes of the IoC library: the actions on many indicators take one of { items: [{ type, value }] }, { list: id }, { incident: id } or { filters: { q, type, verdict, origin, list, expired } }.
  • Async uploads: ?async=true → 202 { jobId }, then poll GET /api/jobs/{jobId}.
  • Webhooks: incident.created/updated/deleted, note.added, upload.completed, ioc.watch_hit (an incident holds an indicator of a watched list); each delivery is HMAC-SHA256 signed (X-Nik-Signature).
  • Operations: 600 requests a minute per client address (10 a minute for signing in), answered 429 beyond; Prometheus metrics at /api/metrics (not published by the bundled nginx); an X-Request-ID on every response.
  • Versioning: the current API is v1 under /api; breaking changes would ship under a new prefix.
